# Carregador SELF/ELF PS4 (experimental)

`core/ps4_loader.{h,cpp}` recebe bytes plaintext do usuário, reconstrói SELF com segmentos presentes, mapeia PT_LOAD/0x61000010 em `GuestMemory`, lê dynlibdata e aplica RELATIVE, 64, GLOB_DAT, JUMP_SLOT e TLS DTPMOD64 (tipo 16, apenas módulo libc local). Não executa código comercial no host e não usa Python/JIT. Rejeita segmentos SELF criptografados/comprimidos, layouts não cobertos, tabelas truncadas e relocações desconhecidas. SHA-1/NID é implementado em C++ portátil.

A API retorna entrada, procparam, metadados TLS de eboot/libc, `init` da libc e imports (`name`, `nid`, `trap`, `address`). Exports da libc são vinculados por NID + identidade/versão de biblioteca e módulo; importações não resolvidas ficam em traps. O alias `libSceLibcInternal` → `libc` é tentado apenas com as demais identidades iguais. A ordem da lista `modules` é a ordem exigida **antes** da entrada do eboot; chamar o inicializador e configurar FS/TCB/TLS na CPU é responsabilidade do integrador. Traps de código são endereços lógicos não mapeados; o integrador registra os ranges no interpretador. Traps de dados são mapeados e zerados para leitura indireta; não implementam serviços do sistema.

`bb-run-eboot Image0 [max_passos] [--libc]` é diagnóstico local: lê `eboot.bin` e opcionalmente `sce_module/libc.prx` do dump do usuário. **Não executa init da libc, não inicializa TLS nem implementa HLE**. Sem `--libc`, no dump local testado, parou após 11 instruções no mesmo import `bzQExy189ZI#q#q` que `bb-run-boot` (imagem BBPROBE2); com `--libc`, parou em outro import após 270 passos, sem prova de inicialização correta. São verificações locais de ponto de parada, não jogo funcionando. Nenhum arquivo do dump foi adicionado ao repositório.

Limites atuais: apenas dois módulos; mapeamento em blocos de imagem inteira (inclusive buracos); falha de carregamento pode deixar mapas parciais; não implementa relocação TLS externa, lazy binding, permissões de execução ou inicialização de módulos. O runner é ferramenta de diagnóstico, não bootstrap de produção. Testes sintéticos exercitam SELF, ELF, imports e bindings, traps de dados, TLS, rejeição de entrada inválida e vetores de NID.
